# 審查請求：估值／動能篩選回測研究設計（審查方：Codex）

你是獨立審查方，以乾淨 session 啟動，只看 repo。全程繁體中文。**不要修改任何檔案、不要執行網路請求、不要 commit**；可以讀檔、跑 `python -m pytest tests/ -q`、跑既有腳本的 `--help`。

## 要審什麼
這是一條「台股 AI／半導體 256 檔、2021–2026、月頻 point-in-time 回測」的研究線，目前結論：估值篩選只有描述力沒有預測力；純相對動能有優勢；下一步測「動能為主、估值排雷」與「動能轉強訊號」。請審**研究設計本身**是否站得住，不是審程式風格。

依序讀：
1. `HANDOFF.md` 最後 15 條（今天的決策脈絡）
2. `docs/tasks/backtest-harness.md`（回測框架規格）與 `backtest_valuation.py`（實作，已通過審查）
3. `backtest/summary.md`（目前結果：L0–L2、M1–M3、C1–C2）
4. `docs/tasks/backtest-momentum-first.md`、`docs/tasks/backtest-t1-turning.md`（尚未執行或執行中的下兩張工單）
5. `build_valuation.py` 的 `--screen` 段（線上篩選器）

## 請針對以下逐項給意見，每項標 嚴重／中／低 與具體建議
1. **前視與資料可見性**：可見日規則（EPS 季末 +45／年報 +75、月營收次月 10 日、法人 ≤ 訊號日）有沒有漏洞；特別檢查 `backtest_valuation.py` 中訊號日基準價、sub 等權、rank 的計算是否有任何跨月或未來資訊。
2. **統計效度**：57 個訊號月、選股數常常個位數、按月勝率的推論力；多重測試問題（已測 L0–L2、M1–M3、C1–C2，再加 D0–D5、T1a–T1x，等於十幾個策略在同一段資料上挑贏家）；該不該做 holdout 或 bootstrap，怎麼做。
3. **基準選擇**：等權 universe 與同 sub 等權當基準是否合理；純動能 C1 贏是不是只是「買到 AI 主鏈」的偽裝，該用什麼對照排除這個解釋。
4. **存活者偏誤與 universe 定義**：universe 用今天的價值鏈平台清單；影響有多大、有沒有低成本的修法。
5. **策略可交易性**：月頻換股、選股 3–10 檔、小型股流動性（部分日均量不到 100 張）、0.6% 成本假設、股利近似法；哪些會讓紙上優勢消失。
6. **下兩張工單的設計**：D 層逐層排除與 T1 二階訊號的定義是否合理、有沒有更標準的動能定義（例如 12−1 個月）應該一起測、法人 20 日條件是否過短。
7. **該砍什麼**：哪些層或工單不值得跑，哪些問題比現在排的更該先回答。
8. **線上篩選器**：`--screen` 的 band_ok／rev_eps_diverge／split_flag 規則與回測結論是否一致，有沒有需要據回測結果改的。
